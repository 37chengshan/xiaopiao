# 今日小票 · 整体设计方案（App + Web）

日期：2026-10-28。状态：**待 tt 确认后分阶段执行**。依据：`docs/SPEC.md`（D1–D11）、`docs/DESIGN.md`、tt 真机验收意见（2026-10-28）、竞品拆解（`~/.agents/skills/app-ui-design/references/teardown-notes.md`）。
取代：先前只讲语音/AI/游戏的草稿。与 SPEC 冲突处以本文为准并在文末「SPEC 变更」列出。

硬约束：**不产生费用**；模型 key 只放云端、绝不进 App/浏览器；账单原文只在本机；AI 只记录、总结、提醒、模拟后果，**不推荐购买/不比价/不下单/不给理财结论**；中英双语必备；演示数据必须标「演示数据」。

## 1. 设计简报

- **产品**：每天一张会说话的 AI 小票。C 端（普通用户）是主角；B 端（小店老板）是同一个 App 里的另一个「身份」。
- **核心任务**：打开 App → 马上能记一笔或跟小票机说话 → 晚上得到一张好玩、想分享的小票。
- **调性**：暖、轻、有手感（纸质小票 + 印章 + 机械声），像一个会陪你聊的小机器，不是财务软件。
- **视觉杠杆**：衬线只用于「小票纸本身」和引导页；其余无衬线；暖纸白底 + 朱砂红只做稀缺强调；大圆角；**有质感的按钮**；2–3 个语义浅色（图标块）点缀避免「素」；深/浅/跟随系统。
- **三条红线（tt 明确）**：tab 根页不放大标题；一屏说明文字 ≤2 段；按钮必须有质感。

## 2. 信息架构与导航

```
首次打开 → 引导（3–4 屏）→ 首页
底部导航（浮动胶囊，5 位）：
  账本 ｜ 洞察 ｜ [ 首页·对话 ]（中间突出主按钮，启动默认页）｜ 圈子 ｜ 我的
```

| Tab | 内容 |
|---|---|
| 首页·对话（中间） | 助手先开口的对话流 + 今日小票入口卡 + 底部输入栏（文字框 + 加号） |
| 账本 | 按日分组的流水、搜索/筛选、编辑/撤销、导入入口 |
| 洞察 | 周报与头衔 · 订阅侦探 · 后悔模拟器（分段控件切换，不另起大标题） |
| 圈子 | 小圈子（情侣/家人）周报与头衔对比 · 小游戏与人格测试 |
| 我的 | 外观（跟随/浅/深）· 语言 · 打印音效/震动 · 记账方式 · 通知自动记账 · 数据与隐私（含数据贡献开关）· **切换到小店版** · 重看引导 · 关于 |

**B 端（小店版）**：在「我的」里点「切换到小店版」进入，有自己的底部导航（人群洞察 · 发起实验 · 结果 · 我的），顶部/我的里有「返回用户版」。C 端导航里永远没有小店。

## 3. 各页面设计

### 3.1 首页·对话（最重要）
- 顶部极简一行：日期 + 今日一句话（零消费日也有话说）；**无大标题**。
- 对话流：助手先开口（补漏记提醒 / 昨日回顾 / 订阅到期提醒）；助手消息无气泡，用户消息浅色气泡；卡片（今日小票、确认卡、周报预告）全宽嵌入流中。
- **今日小票入口卡**：小票缩略（半张纸渐隐）+ 一个有质感的「打印」按钮；零消费日显示「今天钱包休息」。
- **底部输入栏**：文字框 + 加号；**语音就用手机输入法自带的麦克风，App 不做单独语音**。发送后走 §4 解析，生成「确认卡」，用户点确认才入账。
- 加号：手动记一笔 / 导入账单（截图、CSV，本机解析）。
- 空/首次：三个示例 chip（「午饭 32」「昨天打车 18.5」「导入账单」），点一下就填入。

### 3.2 每日小票（仪式感，沿用已实现的 v2）
节奏参考 Nowdex 实测：纸从顶部出纸口**约 6s** 缓慢吐出，约 7 段棘轮声，每段一次轻震；底部药丸「正在打印…跳过」→「向下拖动撕下」；撕下 1:1 跟手、速度投影、旋转飞出；盖章（重震 + 盖章声）；撕下后弹分享 sheet（12 渐变、完整/简版、分享/保存/复制）。
声音：**避免会被系统静音吞掉的通道**（SONIFICATION），在真机上实测 MEDIA/GAME 后定；静音时至少震动并一行小字提示；设置里有声音开关与震动开关。

### 3.3 账本
紧凑顶栏（搜索 + 筛选图标，无大标题）；日分组卡片，行内：分类图标块（语义浅色）· 商户/备注 · 金额（等宽数字，不截断）；左滑编辑/删除；空/1 条/很多条三态；底部浮动「记一笔」不重复出现（因为中间主按钮已承担）。

### 3.4 洞察
分段控件：周报 / 订阅 / 后悔。周报=本周大数字 + 迷你图 + 头衔卡（可分享）；订阅侦探=列表 + 「我已取消」+ **只指引如何取消，不代操作**；后悔模拟器=滑块 + 结果大数字，只陈述后果，不给建议。

### 3.5 圈子
情侣/家人小圈子：一人导入，其他人只收周报和头衔；小游戏入口与人格测试放这里（§6）；与好友的对比只显示聚合。

### 3.6 我的
分组列表，**每项只留标题**（必要时一行灰字），说明收进「了解更多」sheet；无看不懂的术语。

### 3.7 引导（首次打开，可跳过，我的里可重看）
1. 价值：「每天一张会说话的小票」（衬线大字，仅此处）+ 打印动画小样；
2. 自动记账：解释通知读取，**引导里不弹权限，点「去开启」才跳系统设置**，可跳过；
3. 数据底线：「账单原文只在你的手机里」三个图标要点；
4. 个性化：外观三选一 + 声音/震动开关 + 记账方式；完成。

## 4. AI 设计

**输入**：只有文字（含输入法语音转写）。**不做** App 内语音识别、不接任何 ASR。

**一句话记账**（「午饭 32」「昨天打车 18.5」「工资 8000」）→ `{amount: Cents, category, merchant?, date, note, direction}` → 确认卡（原则 1：所有选择由人做）。
- **L0 规则解析器（本机、必做、免费）**：金额（块/元/毛/k/w、中文数字）、日期词、收支方向、分类与商户词典（中英）。解析不出金额就追问。目标覆盖常见口语 ≥90%，语料表驱动单测（中英各 ≥100 句）。
- **L1 云端 LLM 兜底（默认关闭）**：只发这一句文本，key 在云函数 secret，输出 JSON schema 约束并本机再校验，设每日上限。**当前没有你点名的免费服务，所以默认不接**。
- 对话回答范围：只对用户自己的账本做**陈述**（「这周餐饮 ¥236，比上周多 ¥40」）；无 L1 时用模板化回答。

**AI 知识与规则（规则包 `shared/ai-rules/`，两端共用，中英各一套）**：`persona`（语气与禁忌）· `guardrails`（硬规则：不推荐购买/比价/下单/理财结论，订阅只指引不代操作）· `categories`（分类+词典）· `parse-corpus`（语料）· `templates`（开场白/空状态/盖章语）· `titles`（头衔与成就规则）。改规则必跑语料测试。

## 5. 记一笔与默认方式

设置项「记账方式」：文字对话（默认）/ 手动表单 / 导入账单。它决定**打开首页时输入栏的状态**（文字：聚焦输入；手动：直接弹表单；导入：直接选文件）。通知自动记账是后台能力，在「我的」里单独开关，不属于「方式」。默认值存本机偏好，不上云。

## 6. 小游戏与人格测试（含 omp + deepseek 子代理分工）

娱乐定位，每个游戏一行「娱乐，不构成建议」；**游戏表态与真实交易数据分开存、分开标注**；样本 <20 不展示。
- 钱包人格测试：8–10 题 → 12–16 种人格（名字、一句话、搭子人格、可分享卡）。
- 消费场景二选一（现有）：题库 6 → 30+，分主题。
- 小票猜猜看 / 盲盒猜价；今日小任务（只是好玩，不含推荐）；圈子人格对比（聚合）。
- 交付形态：`shared/games/*.json`（题库/人格/文案，中英原生写）+ 校验脚本，UI 由现有 lane 接入。
- **执行**：用 `omp -p --model deepseek/deepseek-v4.1-flash` 在隔离 worktree `../_worktrees/xiaopiao/games-content/` 只产出内容与校验脚本，不碰 App/Web 代码，产出过 guardrails 校验。**会经本机代理调外部模型，开跑前向 tt 确认。**

## 7. 视觉系统（落实红线）

- **底部导航**：浮动圆角胶囊；中间主按钮直径约 58dp、上凸约 16dp；选中项深一层胶囊底。
- **按钮配方**（≈ 目测值，以真机为准）：主按钮纵向渐变（上下约差 6% 明度）+ 顶部 1px 白 28% 内高光 + 主色 28% 柔投影；按下 scale 0.97、阴影收缩、触感；深色模式用发光描边。次按钮浅底 + 描边高光；图标按钮圆形轻浮起。
- **密度预算**：一屏说明文字 ≤2 段；列表行/设置项标题 + 最多一行灰字；字号 4–5 档；强调色一屏 ≤2 处；层次来自语义浅色图标块、大数字、迷你图、卡片底色差。
- **动效**：按压 100–160ms；弹窗 200–400ms；弹簧可打断；尊重「减少动态效果」。
- **触感与声音**：每个仪式节点有对应触感；声音/震动各自可关。

### 7.1 动画与帧率（tt 反馈「现在很粗糙，没有动画细节」）

- **帧率适配**：真机 V2405A 是高刷屏，目标是 60/90/120Hz 都不掉帧。
  - 一切自绘动画（小票打印、撕下、盖章、数字滚动）按**帧时间差 dt** 推进，不用「每帧加固定值」；物理（弹簧/衰减）用 dt 积分。
  - Compose 用 `animate*AsState`/`spring`/`Animatable`，**不在 composition 里分配对象**，高频状态用 `graphicsLayer {}`/`drawBehind` 读取以跳过重组；列表 `key` 稳定；图片/渐变缓存。
  - Web 用 `requestAnimationFrame` 的时间戳算 dt；只动画 `transform`/`opacity`；必要时 `will-change`，用完移除；不在动画里触发布局。
  - 验收：Android 在真机跑 `adb shell dumpsys gfxinfo com.xiaopiao.app framestats` 与 Perfetto/`Jank` 统计，主要流程（切 tab、打印、撕下、开 sheet、滚动账本）janky frames <5%，并**记录刷新率**；Web 用 Performance 面板看 120Hz 下无长任务。
- **动画细节清单**（用 `animate` / `emil-design-eng` / `apple-design` skill 的判断顺序：该不该动 → 目的 → 曲线 → 时长 → 可打断 → 退出）：
  - 按压：按钮 scale 0.97 + 阴影收缩，100–160ms，松手弹回有轻微过冲；
  - 页面/Tab 切换：中间主按钮选中有弹簧位移 + 图标形变，其余 tab 淡入淡出，不做生硬的瞬切；
  - Sheet：弹簧进入、可拖动关闭、速度投影、背景 scrim 渐变与后退；
  - 列表：新增一条从上方滑入并高亮 600ms；删除折叠；金额数字用滚动（NumberTicker）；
  - 对话流：助手消息逐字/逐段出现（可跳过），确认卡弹簧弹出；
  - 空状态、骨架屏、加载有节奏，不闪；
  - 主题切换：整体 200–300ms 交叉淡入，不闪白；
  - 全部尊重「减少动态效果」，并可被打断（动画中再次点击不卡死）。
- 落地后用 `review-animations` / `improve-animations` skill 各出一份审计表，逐条修。

### 7.2 记一笔必须一键可达（tt 反馈「现在还需要下滑才能点到」）

- **记一笔入口永远在拇指区、永远可见，不随内容滚动**：首页的输入栏固定在底部导航上方（键盘弹出时随键盘上移）；账本页不另放悬浮按钮（中间主按钮已承担）。
- 首页内容再长，也不允许把输入栏/「打印」按钮挤出首屏；长内容在对话流里滚动，操作区固定。
- 验收：在 320dp 宽、1.3 字体、有刘海/小屏三种条件下，**打开 App 后一次点击**即可开始记账（聚焦输入或弹出表单）。

## 8. 双语（必备）

默认跟随系统，设置里可切；Android `strings.xml` + `values-en`，Web 轻量字典；英文原生写；金额/日期/星期随语言格式化（金额仍 `Cents`）；AI 回复语言跟随当前语言；规则包与游戏内容中英各一套；**英文也要截图验收**（更长，易挤爆）；免责声明（演示数据、隐私底线）两种语言都在。

## 9. 数据与云

账单原文/截图只在本机解析，云端只存结构化字段；数据贡献默认关、单独授权、可撤回；B 端只给聚合；QMuse 云服务（已确认免费）只用平台默认数据表，不接付费第三方、不用云函数，除非 L1 获批。模型 key 绝不进客户端。
