# 生活（饮食 / 健身 / 运动）· 设计规格 v1

日期：2026-11-02。来源：tt 口述 + 方案评审（`/Users/cc/.claude/plans/app-github-app-ios-web-app-stateless-quiche.md` Phase 1）。上位文档：`docs/SPEC.md`、`docs/APP-DESIGN.md`。

一句话：**和记账同一套做法，记的是吃了什么、练了什么、动了多少**。AI 只负责认出「是什么、大概多少」，热量由本机知识库算；选择永远由人来做。

### 2.1 组内滑动的规则
- 由 shell 层统一接管：只认子元素**没有消费**的横向拖动（|dx| > 1.5·|dy|，且超过 touch slop）。
- 当前页和相邻页跟手平移，位移只在 graphicsLayer 中读取；松手时按距离（> 1/3 屏宽）或速度判断是否切页，切页用 `XpMotion.snappy` 吸附，否则弹回。
- 组的两端做橡皮筋回弹，不会滑到另一组。系统开了「减弱动态效果」时不跟手，直接淡入淡出切换。
- 首帧空闲后，把同组 3 页预热进 keep-alive，第一次滑动也不卡。

## 3. 记一笔（生活）

一个弹层，顶部分段「吃 | 练 | 动」，和记账共用同一套弹层框架与键盘风格。

| 段 | 字段 | 说明 |
|---|---|---|
| 吃 | 餐次（早 / 午 / 晚 / 加餐，按时间自动预选）、食物（搜知识库或手填）、份量、价格（可选）、📷 | 一餐可以有多个食物；没匹配上知识库的食物热量留空，标「未估算」 |
| 练 | 动作（深蹲 / 卧推 / …）× 组 × 次 × 重量 | 力量训练只记量，不臆测热量；需要时按 MET 估算并标「估算」 |
| 动 | 活动（跑步 / 骑行 / 散步 / 游泳 / …）+ 时长或步数 / 距离 | kcal = MET × 体重 kg × 小时 |

- **一句话**：新增 `LifeParser`（规则解析，和 `QuickParser` 同一思路）。例如「午饭一碗牛肉面 25 块」会解析成：餐次=午、食物=牛肉面、份量=1 碗、价格=25；联动打开时同时生成一笔吃饭支出。
- 键盘流程和记账一致：数值 → ↵ → 备注（上方常用短语）→ 保存。

## 4. 生活页

- 今日：摄入 kcal、消耗 kcal、净值；**只有用户自己设了目标**才显示目标环（同预算规则）。
- 时间线：早 / 午 / 晚 / 加餐、训练、运动，一条一行，可编辑可删除，删除后可撤销。
- 「这顿吃了什么？」卡片：联动打开时，抓到一笔餐饮账单（饿了么 37.80）后在这里提示补录，**不推送通知**。
- 周趋势：摄入与消耗的 7 日条形图；吃得最多的 3 种食物。
- 设置项「只记吃了什么，不看热量」：打开后整页隐藏数字，只保留记录。
- **视觉方向先对齐**：动手做 UI 前出 2 个画面方向给 tt 选。

## 5. 知识库与规则

### 5.1 文件
- `app/src/main/assets/life/foods.json`：v1 约 400 条（主食、家常菜、小吃、饮品、水果、零食）。
  ```json
  { "id": "beef-noodle", "name": "牛肉面", "aliases": ["红烧牛肉面", "兰州拉面"], "group": "staple",
    "per100g": { "kcal": 116, "protein": 6.2, "fat": 3.1, "carb": 15.8 },
    "units": [{ "unit": "碗", "grams": 550 }, { "unit": "小碗", "grams": 380 }],
    "cooking": "boil", "source": "recipe:usda-fdc" }
  ```
- `app/src/main/assets/life/activities.json`：约 80 条运动，`{ id, name, aliases, met, source }`，MET 取自 2024 Adult Compendium of Physical Activities。
- 生成脚本放在 `tools/life-kb/`，产物和脚本一起提交。

### 5.2 规则（`domain/life/LifeRules.kt`，纯 Kotlin）
- 份量：一碗、半碗、两个、一份、大杯/中杯、100g、一块 → 克数（优先食物自带单位，其次通用单位表）。
- 饮品糖度：全糖 1.0 / 七分 0.75 / 半糖 0.55 / 三分 0.35 / 无糖 0.15，只乘在糖贡献的那部分热量上。
- 烹饪方式加油：炸 +12g 油 / 100g，煎 +6，炒 +4，蒸、煮 +0（只对标了 `cooking` 的菜品生效）。
- 运动：kcal = MET × 体重 × 小时；没填体重时按 60kg 计算，界面标「估算」。
- 所有数字取整显示；同一顿饭的合计 = 各项之和，不另外估算。

### 5.3 数据来源与版权
- 食材营养数据用 **USDA FoodData Central**（CC0，公共领域）；中式菜品按配方组合计算（食材克数 × 每 100g 数值），每条都写明 `source`。
- **不照搬《中国食物成分表》**（有版权）。只有拿到授权后，才可替换成国标数据。
- MET 值属于学术事实数据，引用 2024 Compendium，并在「关于」页注明出处。

## 7. 和账单联动

设置 → 生活 →「饮食与账单联动」：**关闭 / 询问（默认）/ 自动**。

- 记一顿饭并填了价格：
  - 「自动」：直接生成一笔支出（分类按食物类型：主食/菜品 → 吃饭，饮品 → 奶茶咖啡，零食 → 零食）；
  - 「询问」：保存时问一次「同时记一笔 ¥25？」。
  - 去重：±45 分钟内已有同金额的支出（比如通知已经记了），就只关联，不再新记。
- 抓到一笔餐饮支出：联动不是「关闭」时，生活页出现「这顿吃了什么？」卡片。
- 只在 `food_logs.linkedTxnId` 记录关联关系，账本本身不加字段；删除饮食记录不会删账单，反之亦然。

## 8. 拍照识别

- App：首次点 📷 时弹出单独授权，写明「照片只用于这一次识别，服务器不保存」。照片压缩到长边 ≤512px、≤200KB 后上传。
- 服务端 `POST /v1/life/recognize`（详见 `docs/API-LIFE.md`）：视觉模型返回 `{ items: [{ name, portion_text, grams_estimate, confidence }] }`。图片不落盘、不记录请求体、有限流，key 只放服务端。
- App 用别名去匹配知识库：匹配上的按知识库计算热量；没匹配上的让用户手选或手填。**热量数字永远不由模型直接给出。**

## 9. 隐私与产品原则

- 饮食、体重、运动属于 PIPL 规定的敏感个人信息：首次使用单独告知；**默认只存本机、不同步**；如果以后开放同步，需要再单独授权。
- 不推荐吃什么、不给减重或医疗建议、不做「超标」类的指责性文案；目标只能由用户自己设。
- 不搞连续打卡惩罚、不做体重排行；圈子里最多只分享「今天记了几顿」这类聚合信息（P2），不分享具体食物和热量。
